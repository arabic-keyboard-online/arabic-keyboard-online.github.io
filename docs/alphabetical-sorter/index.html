Order Arabic lists correctly

Arabic alphabetical sorter

Sort names, words, or any Arabic list by the Arabic alphabet, not by Unicode order or the Latin alphabet.

Sorting rules

Everything runs locally in your browser. Nothing is uploaded to a server.

Sorting Arabic with a basic character-code comparison produces the wrong order. Unicode code points do not follow the Arabic alphabet, and many letters have variants, diacritics, and presentation forms. A list that looks sorted to a computer can look random to an Arabic reader.

This tool uses the browser's Arabic collator, which implements the alphabet order used in dictionaries and directories. It sorts line by line, handles Arabic-Indic digits numerically, and can remove duplicates or empty lines before sorting.

The Arabic alphabet order

Arabic dictionary order starts with ا, ب, ت, ث, ج, ح, خ, and continues through د, ذ, ر, ز, س, ش, ص, ض, ط, ظ, ع, غ, ف, ق, ك, ل, م, ن, ه, و, and ي. The collator also places the hamza forms near their base letters and treats diacritics as secondary differences, which is what a phone book or index expects.

Why “sensitivity: base” matters

The sorter compares words at the base-letter level. A word with a fatha and the same word without it land next to each other instead of being separated by every other entry. Numeric sorting is enabled too, so item 2 comes before item 10 rather than after it.

Case is irrelevant for Arabic, but it matters for mixed lists. Latin names are compared with the same collator, which keeps a bilingual list predictable instead of dropping English entries to the end alphabetically by byte value.

How to sort a list

  1. Paste one item per line. Extra spaces at the edges are trimmed.
  2. Choose ascending (A → ي) or descending (ي → A).
  3. Turn on duplicate removal if the list came from a form or a merge.
  4. Turn on empty-line skipping if the paste includes blank rows.
  5. Copy the sorted list back into your spreadsheet, document, or code.

The result updates as you type. The line counters show how many lines went in and how many remain after filtering.

Duplicates and near-duplicates

Duplicate removal is case-insensitive for Latin and ignores nothing else. Two Arabic words that differ only in diacritics are treated as different strings, because the marks can change pronunciation and meaning. If you want to merge them, remove the harakat first with the harakat remover, then sort and deduplicate.

Whitespace inside a line is preserved. If a spreadsheet export adds trailing tabs, they remain visible in the output but do not usually affect the order. Clean them with the text cleaner if they matter.

Where an Arabic sorter helps

  • Alphabetizing patient or student lists before printing.
  • Sorting a glossary, index, or table of contents.
  • Checking which names appear twice in a merged contact list.
  • Arranging a vocabulary list for a class, from أ to ي.

One item per line: the tool sorts lines, not comma-separated cells. Split a comma-separated list first, or paste it into a spreadsheet and copy the column.

Quick answers

Frequently asked questions

Does it use the real Arabic alphabet order?

Yes. It uses the browser Arabic collator, which follows dictionary order rather than Unicode code-point order. Hamza forms and diacritics are handled as secondary differences.

Can it sort numbers correctly?

Yes. Numeric sorting is enabled, so 2 comes before 10. Arabic-Indic and Western digits are compared as numbers, not as text characters.

How does duplicate removal work?

It compares trimmed lines and ignores Latin case. Two lines that differ only in Arabic harakat are kept as separate entries because the marks can change the word.

Can I sort a comma-separated list?

The tool works line by line. Replace commas with line breaks first, or paste the column from a spreadsheet, then sort.

Is there a limit on the number of lines?

There is no fixed limit beyond what your browser can handle. Very large pastes may take a moment; the sort runs locally and does not upload anything.
