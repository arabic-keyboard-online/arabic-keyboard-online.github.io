Arabic to Unified Braille

Arabic Braille translator

Convert Arabic letters, numbers, and punctuation into Unicode braille cells that read in the correct order for a blind reader.

Braille cellsLTR
Braille options

Braille is read left to right in the order the Arabic text is read. Numbers use one number sign per digit run, and Latin runs stay left to right.

Everything runs locally in your browser. Nothing is uploaded to a server.

Arabic Braille uses the same six-dot cell as Latin Braille but assigns different patterns to Arabic letters. A braille reader moves left to right across the cells, following the order of the Arabic text, not the visual right-to-left direction of the printed page. That distinction is the source of many broken converters: reversing the whole string produces cells that look plausible but read backward.

This translator keeps the reading order. It maps each Arabic letter to its Unified Arabic Braille cell, groups digit runs under a number sign, keeps Latin runs readable, and places shadda before its consonant as Arabic Braille requires. The output is Unicode braille, ready to copy into a braille editor or send to an embosser.

Reading order, not visual order

In print, Arabic starts on the right. In braille, the reader starts on the left and follows the sequence of letters. The first letter of an Arabic word is therefore the leftmost cell of that word in the braille line. The converter writes cells in logical reading order, so مرحبا becomes the cells for م, ر, ح, ب, ا in that order.

If a legacy workflow expects a mirrored visual string, this tool is not the right fit. Mirrored output is a niche compatibility mode, not standard Arabic Braille.

The Arabic Braille alphabet

Unified Arabic Braille assigns a distinct cell to each Arabic letter, including the hamza forms and the letters used in Persian and Urdu. The mapping covers ا through ي, the ta marbuta, alef maqsura, and the additional letters. The tool also recognizes the lam-alef ligature as a single cell rather than two separate letters.

Punctuation has its own cells: the Arabic comma, semicolon, question mark, and the usual period and colon. A space becomes a blank braille cell, which preserves word boundaries for the reader.

Harakat and shadda

Vowel marks are optional in the output. With harakat enabled, each fatha, kasra, damma, tanwin, sukun, and shadda gets its braille cell. The shadda is placed before the consonant it doubles, following Arabic Braille convention, rather than after it as in print. With harakat disabled, the output is shorter and easier to scan but loses pronunciation information.

For a beginner learning the alphabet, keep the marks on. For a long document where the print original is unvocalized, turn them off to match the source.

Numbers and number signs

Braille digits reuse the letters ا to ي, so a number sign is needed to tell the reader that the next cells are digits. The converter inserts one number sign at the start of each digit run and then writes the digits in their normal order. A number such as 2026 becomes a single sign followed by four digit cells, not four signs.

Western digits and Arabic-Indic digits are both accepted. Latin words inside the text stay in left-to-right order, because reversing an English name would make it unreadable.

Using the output

Press Copy and paste the cells into a braille editor, a print workflow, or a teaching document. The Unicode braille block displays with a font that contains braille patterns; some default fonts show empty boxes. On Windows, Segoe UI Symbol includes the block. If you plan to emboss, import the text into software that understands Unicode braille rather than printing the screen.

Check before embossing: braille standards vary by country and by whether the text is literary or scientific. Confirm the local convention, especially for numbers and foreign words.

Quick answers

Frequently asked questions

Is this Unified Arabic Braille?

Yes. The letters use the Unified Arabic Braille assignments, with a lam-alef ligature cell, Arabic punctuation, and a number sign for digit runs.

Why are the cells not reversed?

Braille is read left to right in the order the Arabic text is read. Reversing the string would make the reader start at the last letter of the sentence.

Can I remove the harakat from the braille?

Yes. Uncheck “Include harakat and shadda”. The letters remain, but the vowel and doubling information is dropped.

Does it handle English words and numbers?

Yes. Latin runs stay in left-to-right order, and digit runs get one number sign followed by the digits. Arabic-Indic and Western digits are both accepted.

Can I send the result to a braille embosser?

The output is Unicode braille. Import it into braille production software that supports the braille block; printing the screen does not produce embossed dots.
