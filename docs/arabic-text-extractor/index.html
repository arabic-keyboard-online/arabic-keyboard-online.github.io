Separate Arabic from noise

Arabic text extractor

Paste a mixed page, table, or OCR dump and keep only the Arabic characters, with optional numbers, punctuation, and line breaks.

Keep in the result
Extracted Arabic

Everything runs locally in your browser. Nothing is uploaded to a server.

Arabic content is often buried in material that is not Arabic: a bilingual web page, an OCR export with English interface labels, a spreadsheet with codes, or a PDF where every line includes a page number. Copying the useful part by hand is slow and error-prone.

This extractor scans the text and keeps only the characters you allow. By default it keeps Arabic letters, numbers, punctuation, spaces, and line breaks. Latin letters, emoji, symbols, markup, and control characters are removed. The result is a clean Arabic body that you can paste into a document, subtitle, or dataset.

What counts as Arabic

The tool accepts the main Arabic block, the Arabic Supplement and Extended blocks, and the Arabic presentation forms. That covers ordinary letters, ڭ, ڨ, پ, چ, ژ, and گ, as well as Persian and Urdu additions. It does not keep Latin transliteration, Cyrillic, Hebrew, or CJK characters.

Spaces and tabs are always allowed because words need separation. Tabs are normalized to spaces when line breaks are off. Runs of spaces are collapsed, and three or more newlines are reduced to two when line breaks are on.

Choosing what to keep

  • Numbers keeps both Western digits and Arabic-Indic digits. Turn it off when you want words only, such as a vocabulary list.
  • Punctuation keeps the common Arabic and Latin marks: comma, period, question mark, semicolon, colon, quotes, brackets, and guillemets.
  • Harakat keeps the short vowels and shadda. Leave it off to produce unvocalized text for search or word counting.
  • Line breaks preserves the paragraph structure. Turn it off to flatten everything into one paragraph.

Each option changes the allowlist immediately, so you can compare results without re-pasting.

Practical uses

Cleaning OCR output

OCR often inserts stray Latin characters where it misread a shape. Extracting only Arabic removes the noise but keeps the words and numbers you need to check.

Separating a bilingual page

If a page alternates English navigation with Arabic content, extraction leaves the Arabic paragraphs in place and drops the interface text. Turn off line breaks to merge the result into a single block.

Preparing a text dataset

For frequency analysis or language modeling, remove markup, URLs, and Latin code first. The frequency counter then sees only Arabic tokens, which produces a more meaningful word list.

What the extractor cannot preserve

It is a character filter, not a parser. It does not know that a particular Latin word is a name that should stay, or that a symbol is meaningful in a mathematical formula. It also does not fix broken Arabic letters or reversed order; those need a shaping or bidi fix. If the source has disconnected presentation forms, use the Photoshop fixer or retype the line.

Because the filter is aggressive, keep the original text somewhere until you have checked the result. The editor does not keep a history.

Local and instant

The extraction runs in your browser. Nothing is uploaded, and the text disappears when the page is closed. That makes the tool suitable for internal documents and personal notes as well as public web content.

Quick answers

Frequently asked questions

Which characters does the extractor keep by default?

Arabic letters, spaces, line breaks, numbers, and common punctuation. Latin letters, emoji, symbols, markup, and control characters are removed unless they fall under an option you enable.

Can I keep the harakat in the result?

Yes. Turn on the Harakat option. Leave it off if you want plain, unvocalized Arabic for search, counting, or dataset preparation.

Does it remove English words only?

It removes every character outside the allowlist, including Latin letters, Cyrillic, emoji, and symbols. Numbers and punctuation can be kept with their own options.

Can it extract Arabic from a PDF?

Paste the text after copying it from the PDF. If the PDF uses images, run OCR first. The extractor cleans the copied text but does not read images itself.

Will it fix reversed or disconnected Arabic?

No. It filters characters. Reversed order is a bidirectional issue in the source app, and disconnected letters need presentation-form conversion.
